## Runtime boundary

`STARTECH_EXTRACTION_ENABLED=true` only after review. `safeGet` uses HTTPS, public-address DNS validation and address pinning to the actual TLS socket; fixed host; no redirect following; 8-second request deadline, 3-second DNS deadline, 1.5 MB response cap. Robots must be retrievable as text/plain and affirmatively allow the requested path. A failed source pauses the adapter for one minute. Cache holds at most 100 extracted pages for one hour and preserves the original retrieval time.

`parseProduct` only accepts one Product with one non-aggregate Offer in BDT. It rejects multiple products/offers and ambiguous price text. It does not invent shipping, mandatory fees, policies, reviews, ratings or seller affiliations. Condition remains unknown unless explicitly represented as new. Therefore an extracted page alone will typically not qualify for cheapest confirmed delivered.

## Live verification procedure

After approval and enabled source configuration:

```sh
LIVE_SMOKE=true STARTECH_EXTRACTION_ENABLED=true npm run test:live -- https://www.startech.com.bd/APPROVED-PRODUCT-PATH
```

Supply actual current product URLs, not the placeholder. Save timestamp, URL, extracted title/price and a manual page comparison. The handoff's three-pages/across-two-sources gate is **not met** by a single Star Tech adapter. A second permitted source or approved feed is still needed. Never enable Ryans automation to satisfy a count.

## Research versus product evidence

Research confirmed that Star Tech robots is retrievable and gives path rules. It did not verify any offer through this app. An indexed seller page or search result does not establish present stock, correct variant or delivered cost. No researched price was inserted into the application.
